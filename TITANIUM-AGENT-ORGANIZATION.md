## Recommended Organization

### Layer 1: Management and Governance

#### 1. Titanium Manager / Orchestrator

**This should be the only agent that normally receives broad user requests.**

**Responsibilities:**
- ✅ Understand the business objective
- ✅ Create the campaign or task plan
- ✅ Select the appropriate specialist
- ✅ Provide the specialist with structured context
- ✅ Collect specialist outputs
- ✅ Detect contradictions
- ✅ Request approvals
- ✅ Verify completion
- ✅ Produce the final report

**Should NOT Normally:**
- ❌ Write directly to every platform
- ❌ Send outreach
- ❌ Change prices
- ❌ Publish content
- ❌ Modify customer consent
- ❌ Issue refunds
- ❌ Revoke course access

**Authority:**
> The Manager should have broad read visibility but limited write authority.

---

#### 2. Knowledge Curator and Audit Agent

**This agent maintains OpenClaw's expertise.**

**Responsibilities:**
- ✅ Review proposed additions to permanent memory
- ✅ Detect conflicting or outdated instructions
- ✅ Maintain product documentation versions
- ✅ Review failed workflows
- ✅ Manage evaluation scenarios
- ✅ Produce a knowledge-health report
- ✅ Mark outdated material as deprecated

**Authority:**
> This agent should be read-only across operational platforms. It should update knowledge only through an approved process.

**Mission:** Discover timely, locally relevant subjects that can become useful content or campaigns.

**Inputs:**

**Outputs:**

- Source quality

#### 5. SEO Architecture Agent

**Recommended: Merge these two current agents:**
- Metadata & Schema Optimizer
- Internal Link Architect

**The combined agent would own:**
- Titles and descriptions
- Canonical recommendations
- Structured-data selection
- Schema validation
- Internal-link opportunities
- Anchor-text recommendations

> A different prompt alone is not a sufficient reason to create another agent. Create a separate agent when the function needs different knowledge, tools, permissions, evaluations or accountability.

## Give Every Agent an Operating Contract

**Every agent definition should answer the following:**

### 1. Mission
One sentence describing the outcome it owns.

### 2. Trigger Conditions
Examples of requests or events that should activate it.

### 3. Required Inputs
Information it must receive before beginning.

### 4. Authoritative Sources
The documentation and platforms it must trust.

### 5. Allowed Tools
Only the platforms and operations needed for its work.

### 6. Prohibited Actions
Actions it must never perform.

### 7. Approval Gates
Exactly which actions require human authorization.

### 8. Output Contract
The structured output expected by the Manager.

### 9. Verification
How it proves that its work succeeded.

### 10. Escalation Rules
When it must stop and return the task to a human.

### 11. Memory Boundaries
What it may retain and what must stay in the source platform.

### 12. Performance Measures
How the organization evaluates the agent.

## Standardize Agent Handoffs

**Agents should not exchange large, informal paragraphs. Use a structured task envelope:**

### Task Assignment

```yaml
task_id: task-unique-id
campaign_id: campaign-unique-id
objective: Generate qualified local-business leads
assigned_agent: local-intelligence-scout
audience: Independent local retailers
inputs:
  location: Austin
  date_range: current-quarter
source_requirements:
  official_sources_required: true
requested_output:
  - verified_trends
  - content_angles
  - supporting_sources
constraints:
  - no_unverified_statistics
  - no_publication
approval_required: false
due_priority: normal
```

### Task Result

```yaml
task_id: task-unique-id
status: completed
findings: []
sources: []
confidence: high
risks: []
recommended_next_agent: content-strategist
approval_needed: false
memory_proposals: []
```

**Purpose:**
> This makes work traceable and prevents context from becoming distorted during handoffs.

## Permission Matrix

| Action | Specialist | Manager | Human Approval |
|--------|-----------|---------|----------------|
| **Research trends** | Execute | Review | No |
| **Draft content** | Execute | Review | Usually no |
| **Recommend metadata** | Execute | Review | No |
| **Change site metadata** | Prepare | Coordinate | Yes initially |
| **Publish a page** | Prepare | Coordinate | Yes |
| **Send outreach** | Draft | Coordinate | Yes |
| **Update ordinary CRM tags** | CRM agent | Monitor | According to approved rules |
| **Override consent** | Never | Never | Restricted human process |
| **Change price** | Revenue agent prepares | Reviews | Yes |
| **Enroll verified purchase** | Delivery agent | Monitors | Automatic only after testing |
| **Revoke access** | Prepare | Coordinate | Yes |
| **Update permanent knowledge** | Propose | Review | Knowledge-owner approval |

**Security:**
> Do not give every agent every credential. Enter credentials only through ClawLauncher's protected configuration, never in prompts or agent instructions.
